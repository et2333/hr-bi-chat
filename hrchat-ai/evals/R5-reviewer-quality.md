# R5 结构洞察与 Reviewer 离线评测

2026-10-11。程序计算统计重点，Analyst 选择和解释事实，Reviewer 可用 `highlight_fact_ids` 补齐遗漏（最多 6 项）。只允许引用已校验的部门证据中的事实，不能编写新数值或原因；单任务仍最多 4 次模型、6 次工具尝试、1 次每日补查。字段为增量扩展，旧结果缺少结构字段时页面仍可读。

## 产品行为

- “统计变化重点”展示增加/减少最多部门（含并列）、增减相抵数量，以及绝对变化最大部门组在全部绝对变化中的份额。不人为设置“高风险/集中”阈值，不将份额称为离职率；基期为零不计算增长率。
- 结构事实和完整部门表在程序、单 Agent、双 Agent 模式均存在。AI 引用覆盖不足不代表程序漏算。
- Reviewer 收到 `focus_fact_ids` / `missing_focus_fact_ids` 的程序提示，补齐重点不能计作独立发现。非法补充不入结果，保留 PARTIAL 与原因。
- 补查过程区分：待核查项→申请依据→已核验每日证据→解读已完成/仍不足。允许补查不等于查询成功；数据取得不等于已完成解读。尚不能确认的真实原因继续保留。

## 控制实验

`evals.reviewer_quality` 包含 8 类场景：正确草稿、遗漏部门、虚构事实、因果冒充事实、零基期虚构增长率、无必要补查、误删正确结论、有效补查。每类运行程序、单角色脚本、双角色参考脚本、双角色故障脚本，共 32 次。

脚本只替换模型/Java 传输，运行实际 LangGraph、AgentScope 和契约；**不访问供应商 API，不证明真实模型的检错率或多 Agent 优于单 Agent**。参考脚本表现好是受控输入，不是泛化效果。

指标保留分子/分母：Reviewer 删除错误项的比例、误删正确项比例、AI 结论关键事实覆盖、无必要补查请求/实际查询数、角色调用数。没有错误样本时检错率为 null；不把程序最后过滤掉的错误算给 Reviewer。记录程序预先标记的删除项、程序提示后补充的重点、其它尚待裁定的删除项。脚本 Token/实际费用不作估算，报告为未知。

在 `hrchat-ai` 中运行：

```powershell
.\.venv\Scripts\python.exe -m evals.reviewer_quality
.\.venv\Scripts\python.exe -m evals.s6_smoke --browser
```

第二条需要已构建 Java JAR、安装本地浏览器依赖，使用隔离服务端口 18096/18097 和前端 5199；全部为本地 H2+脚本模型，不调用付费 API。
