# R5 检索质量评测 v1

60 条由助手起草的合成问句/标签，**人工业务复核待完成**，不是真实用户数据或行业基准。20 个表达家族，每家族 3 个改写；dev/frozen 各 10 家族、30 题。与既有语料/题集做规范化完全重合检查和近似重复提示；这不保证语义独立或未受已知业务知识影响。

- `relevance`：只用于检索评分的相关口径和示例模式，不输入排序器。不支持的问题对应的不可执行口径也可以是正确检索目标。
- `expected`：人工待审的后续**任务期望**（动作/指标/模式/组织/右开期间），本 runner 不执行或评分任务；不能写成端到端成功率。
- `prior_task`：多轮期望的显式前置状态。检索仍只接收当前问句；未提指标的追问不计指标检索命中，报告分母排除，不能偷偷把继承的金标加到 query。
- 模糊指标样本有三个候选，使用 Recall@K 看候选覆盖，不能据此决定执行。按动作和类别单列，避免容易命中的多标签题掩盖单目标错误。
- `example_hit_at_2` 只衡量同指标同模式的模板命中，不评价字段抽取、条件复制或澄清正确性。

固定模拟候选池为 63 条口径（3 可执行+60 非可执行）和 36 个现有示例。模拟干扰项仍仅用于评测，不进入日常目录。四臂同池：BM25、纯 BGE、BGE+BM25/RRF、混合+可执行先验；先验收益单独比较，不归功于向量模型。

`MRR` 使用完整排名；`MRR@2` 在正确项排名超过 2 时计 0。`Hit@K` 至少一个相关项；`Recall@K` 命中相关项数量/全部相关项数量。`metric_top1_error` 为错误或空首项；`top1_nonexecutable` 只是不可执行首项占比；`unsupported_executable_top1` 是**检索替换风险**，不是实际错误执行率。

BM25 可能只返回非零匹配项，未返回的相关项仍计失败，不缩小标签分母。逐题报告保留完整排名；配对差值按表达家族 bootstrap，不能把三个改写视为三个独立业务场景。样本少，区间仅作探索性分析。

在 `hrchat-ai` 执行（均零付费调用，本地模型需已下载）：

```powershell
.\.venv\Scripts\python.exe -m evals.retrieval_quality --validate
.\.venv\Scripts\python.exe -m evals.retrieval_quality --split dev
.\.venv\Scripts\python.exe -m evals.retrieval_quality --split frozen
```

报告写入被忽略的 `docs/evaluation-runs/r5-retrieval-*/report.json`。记录数据/代码/语料/模型指纹及首次模型加载、文档编码、热文档缓存下的查询耗时。每个向量臂重新编码 query，避免先跑的方案替后跑的方案支付编码时间；不是 API 延迟或生产 SLA。

先检查数据标签与 scorer，再冻结运行。首次 frozen 报告之后不据此调参再宣称独立提升；若修改模型/先验/Prompt，旧结果保留作回归，重新招募表达或建立新测试集。原 R4 holdout/hard 已用于分析调参，只保留为诊断回归。

真实模型阶段另行授权，固定少量问句/权限/时期/模型、关闭修复与自动重跑；根据完整任务及真实使用量比较。紧凑目录的 Token 节省实验尚未实现；当前运行时仍保留完整目录。
