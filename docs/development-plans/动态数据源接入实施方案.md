# 动态数据源接入实施方案

> 版本：v1.0 ｜ 日期：2026-09-28
> 关联文档：《QuickBI对标差距分析.md》第 1 节、《语义层管理UI对标QuickBI补全实施方案.md》
> 状态：待评审（本文仅为实施方案，不含代码变更）

---

## 1. 背景与目标

差距分析第 1 节核心结论：当前系统数据靠预置 H2 内存事实表（`dim_employee`/`dim_org`/`fact_*`），数据源页面（`admin/data/index.vue`）仅有只读监控视图，**不能动态接库**。维度引擎元数据化完成后，"维度"已可配置，但指标公式中的物理表仍只能落在唯一的主库（H2）上。

**本方案目标**：让管理员通过 UI 完成外部数据库的注册、连通性测试与生命周期管理；让指标可以绑定到指定数据源，问数/图表/表格链路将 SQL 路由到目标库执行。对标 Quick BI「数据构建 → 数据源连接（在线测试/连接池管理）」。

**非目标（本方案不做）**：

- 不做数据集建模（单表/Join/自定义 SQL/数据集组合）——依赖本方案，单独立项；
- 不做 ETL/数据集成/Quick 加速引擎（抽取、列存、缓存）；
- 不做 Excel/CSV 文件上传；
- 不做自动方言翻译引擎（仅处理已识别的少量不可移植子句，见第 7 节）。

## 2. 范围分层

| 层级 | 内容 | 支撑数据库 |
| --- | --- | --- |
| **P0** | 数据源注册表、CRUD、在线测试、Hikari 连接池托管（懒加载/刷新/停用/销毁）、凭据加密存储、指标绑定数据源、查询链路按绑定路由、前端数据源接入页与指标编辑器数据源选择、方言适配（LIMIT 子句） | MySQL、PostgreSQL、H2 |
| P1 | 库表/字段元数据 introspection 接口与 UI（为数据集建模铺路）、ClickHouse/Doris/Oracle/SQL Server 驱动、连接池监控指标（活跃/等待连接）、按数据源的 SQL 校验规则细化 | + ClickHouse/Doris 等 |
| P2 | 信创数据库（达梦/人大金仓）、SSL/Kerberos、外部 KMS/Vault 凭据、数据源级行权限策略、查询结果缓存/加速 | + 达梦/金仓 |

## 3. 现状与关键约束（代码证据）

| 事实 | 位置 | 对方案的影响 |
| --- | --- | --- |
| 查询执行唯一入口 | [QueryExecService.java](../../hrchat-server/hrchat-query-exec/src/main/java/com/hrchat/queryexec/service/QueryExecService.java)：`executeReadonly(sql)` / `executeWithTimeout(sql, s)` | 增加数据源参数重载，旧签名保留 |
| JDBC 执行器构造时注入唯一主 `DataSource` | [JdbcQueryExecutor.java](../../hrchat-server/hrchat-query-exec/src/main/java/com/hrchat/queryexec/service/impl/JdbcQueryExecutor.java#L39)：`dataSource.getConnection()` | 改为可按编码取得目标数据源，主库为默认兜底 |
| SQL 生成点 | [ReportChartService.java](../../hrchat-server/hrchat-report/src/main/java/com/hrchat/report/service/ReportChartService.java)：`buildDirectSql/buildRatioSql`，表名取自指标公式 | 执行时透传指标绑定的数据源编码；标量子查询的 `FETCH FIRST 1 ROW ONLY` 需按方言渲染 |
| 生产环境 `executeReadonly` 调用点共 5 处 | `ReportChartService:152`、`ReportTableService:71,116`、`LocalAgentRuntimeImpl:245,256,954` | 全部切换为数据源感知重载 |
| 已有集成数据源表 `itg_datasource` | [H2 V1 baseline](../../hrchat-server/hrchat-bootstrap/src/main/resources/db/migration/h2/V1__baseline.sql)：字段为 `sync_mode/cred_ref/schedule_cron`，语义是"同步/集成"配置，且由监控页种子数据占用 | **不复用**，另建查询数据源注册表，避免语义混淆与跨模块实体依赖 |
| 模块依赖方向 | `hrchat-query-exec` → `hrchat-authz`/`hrchat-api`；`hrchat-admin` → report/model/semantic/audit 等（**未显式依赖** query-exec，经 report 传递可见）；`hrchat-semantic` 不依赖 query-exec | 核心逻辑放 query-exec；管理 Controller 放 admin，admin pom 补显式依赖 |
| 连接池 | `spring-boot-starter-jdbc` 已传递引入 HikariCP | 无需新依赖即可用 `HikariDataSource` |
| 多租户 | `TenantContextHolder`（ThreadLocal，`X-Tenant-No`），当前种子单租户 T000 | 注册表加 `tenant_no`，连接池按 `租户::编码` 隔离 |
| 权限/审计 | 权限串 `admin:data:read`/`admin:data:manage` 已存在；`AuditEvents` 可扩展事件常量 | 直接复用权限串，新增 4 个数据源审计事件 |
| MyBatis 扫描 | `HrchatApplication`：`@MapperScan(basePackages="com.hrchat", annotationClass=Mapper.class)` | query-exec 新 Mapper 标 `@Mapper` 即自动生效 |

**关键架构约束**：MyBatis-Plus 对系统表（biz_*、itg_*、qry_*）的元数据查询必须**始终走主库**；只有用户分析 SQL（经 JdbcQueryExecutor 的路径）允许路由。因此**不采用**全局 `AbstractRoutingDataSource`（会波及系统查询），路由只收敛在执行器内部。

## 4. 总体架构设计

### 4.1 模块归属

```
hrchat-query-exec（核心，全部无 Web 依赖）
├── entity/QryDatasource.java          注册表实体（@TableName qry_datasource）
├── mapper/QryDatasourceMapper.java    @Mapper，MyBatis-Plus
├── dto/                               DatasourceConfig / View / TestRequest
├── crypto/PasswordCipher.java         AES-GCM 加解密
├── dialect/SqlDialect.java            H2 / MYSQL / POSTGRE 方言（limit 子句等）
├── datasource/DataSourceRegistry.java 连接池注册中心（懒加载/缓存/刷新/销毁）
└── service/DynamicDatasourceService.java  CRUD + 在线测试（无审计、无 HTTP）

hrchat-admin
├── pom.xml                            补 hrchat-query-exec 显式依赖
└── controller/DynamicDatasourceController.java
      权限校验 + 审计记录 + 委托 DynamicDatasourceService；
      DELETE 前经 SemanticMetaService 检查指标引用（admin 已依赖 semantic）

hrchat-semantic
└── BizMetric / MetricDetail 增加 datasourceCode 字段透传（不引入 query-exec 依赖，
  数据源合法性在执行期校验；编辑器侧由前端列表接口约束）
```

### 4.2 执行链路（改造后）

```
NLQ/图表/表格
  → 解析得到 MetricDetail（含 datasourceCode，可空）
  → SqlRewriteService.rewrite / validate（不变）
  → QueryExecService.executeReadonly(sql, datasourceCode)   ← 新增重载
  → JdbcQueryExecutor.execute(sql, timeout, datasourceCode)
       ds = registry.get(tenant, datasourceCode)  // 不存在/停用 → PARAM_INVALID
          ?? primaryDataSource                    // code 为空 → 主库（H2）
       try (Connection = ds.getConnection()) ...  // 其余逻辑不变
```

- 比率指标（`code1/code2`）：P0 约束分子、分母必须绑定同一数据源（均空或编码相同），否则 `PARSE_FAILED`："暂不支持跨数据源比率指标"。
- `DataSourceRegistry`：`ConcurrentHashMap<cacheKey, HikariDataSource>`；配置更新/停用 → `close()` 并逐出；删除 → 先查引用（admin 层）再关池；`@PreDestroy` 全量关闭。
- 连接池创建失败（驱动缺失、URL 非法、连不通）→ 不落缓存，返回 PARAM_INVALID 与原始错误摘要。

## 5. 数据模型变更

### 5.1 新表 `qry_datasource`（新增 Flyway 版本迁移，query-exec 模块实体）

```sql
CREATE TABLE qry_datasource (
  id              BIGINT AUTO_INCREMENT,
  tenant_no       VARCHAR(32)  NOT NULL DEFAULT 'T000',
  ds_code         VARCHAR(64)  NOT NULL,
  ds_name         VARCHAR(128) NOT NULL,
  db_type         VARCHAR(32)  NOT NULL,           -- H2 / MYSQL / POSTGRE
  jdbc_url        VARCHAR(512) NOT NULL,
  db_username     VARCHAR(128) DEFAULT NULL,
  password_enc    VARCHAR(512) DEFAULT NULL,       -- AES-GCM 密文，API 永不回显
  pool_config     VARCHAR(512) DEFAULT NULL,       -- JSON: maxPoolSize/connTimeout/idleTimeout
  status          TINYINT NOT NULL DEFAULT 1,      -- 1启用 0停用
  last_test_at    DATETIME(3) DEFAULT NULL,
  last_test_ok    TINYINT(1) DEFAULT NULL,
  is_deleted      TINYINT(1) NOT NULL DEFAULT 0,
  created_by      VARCHAR(64) DEFAULT NULL,
  created_at      DATETIME(3) DEFAULT CURRENT_TIMESTAMP(3),
  updated_at      DATETIME(3) DEFAULT CURRENT_TIMESTAMP(3),
  PRIMARY KEY (id),
  UNIQUE (tenant_no, ds_code)
);
```

池配置默认值（`pool_config` 为空时）：maxPoolSize=5、connectionTimeout=5s、idleTimeout=60s。受 H2 演示规模限制，P0 不暴露过深的池参数。

### 5.2 `biz_metric` 加列

```sql
ALTER TABLE biz_metric ADD COLUMN datasource_code VARCHAR(64) DEFAULT NULL;
-- 空 = 主库（现有指标全部保持空，行为不变）
```

- P0 只在 `biz_metric` 加列，版本表不加：数据源是指标的运行环境属性，不随草稿版本变更；
- 历史指标 `datasource_code` 全为 NULL → 全部路由主库，零回归。

## 6. 凭据安全

1. `PasswordCipher`：AES-256-GCM（JDK 原生 `javax.crypto`，无新依赖）；密文格式 `base64(iv|ciphertext|tag)`。
2. 密钥来源配置项 `hrchat.security.datasource-crypto-key`（Base64）：
   - local profile：内置开发默认密钥，启动日志打 WARN；
   - 生产部署未配置 → 启动失败（fail fast）。
3. API 行为：密码**只写不读**。详情/列表接口不含 password 字段；PATCH 时 password 缺省或为空 = 不修改。
4. 审计只记录数据源编码/操作人，不记录 URL 参数、用户名、密码。

## 7. SQL 方言策略

当前生成 SQL 绝大部分可移植（`COUNT/SUM/AVG/GROUP BY/LEFT JOIN/NULLIF/IN 子查询`）。已识别的不可移植点：

| 子句 | 现状 | P0 处理 |
| --- | --- | --- |
| 维度标量子查询限一行 | `FETCH FIRST 1 ROW ONLY`（H2/PG 支持，MySQL 不支持） | 经 `SqlDialect.limitOne()` 渲染：H2/PG → `FETCH FIRST 1 ROW ONLY`；MYSQL → `LIMIT 1`（置于子查询末尾，需调整拼接位置） |
| 标识符引用 | 全部不引号 | 维持不引号（入库白名单 `^[a-z_][a-z0-9_]{0,63}$` 已保证安全） |

方言由数据源 `db_type` 决定，随 datasourceCode 一起从执行上下文取得。报表/表格构造 SQL 的方法签名需接收 `SqlDialect`（P0 只影响维度标量子查询拼接处）。不做更深的方言翻译——用户自定义公式 SQL 本身需面向目标库书写。

## 8. API 设计

管理 Controller 位于 hrchat-admin，基址 `/api/v1/admin/datasources`，与既有监控路由（`GET /datasources`、`/sync-jobs`）**方法级不冲突**：

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/datasources/registry` | admin:data:read | 注册表列表（不含密码，含 last_test 状态） |
| POST | `/datasources/registry` | admin:data:manage | 新建：`{code,name,dbType,jdbcUrl,username,password,poolConfig}` |
| GET | `/datasources/registry/{id}` | admin:data:read | 详情（无密码） |
| PATCH | `/datasources/registry/{id}` | admin:data:manage | 更新（password 空=不变）；更新后刷新连接池 |
| DELETE | `/datasources/registry/{id}` | admin:data:manage | 软删；**有指标绑定时拒绝**（经 SemanticMetaService 查 biz_metric.datasource_code）；关池 |
| POST | `/datasources/registry/{id}:test` | admin:data:manage | 测试已保存配置（`SELECT 1`，5s 超时），回写 last_test_* |
| POST | `/datasources/test` | admin:data:manage | 保存前测试（请求体直连，不落库） |

审计事件（AuditEvents 新增常量）：`DATASOURCE_CREATE / UPDATE / DELETE / TEST`。

错误语义沿用现有约定：参数/驱动/连通问题 → 400 + 业务文案（前端 http 拦截器已能提取 `data.message`）；执行期未知数据源编码 → `PARAM_INVALID "数据源[X]未配置或已停用"`。

## 10. P0 实施任务分解

1. **DDL 与实体**：qry_datasource 建表；biz_metric 加 datasource_code；QryDatasource 实体（@TableLogic）、QryDatasourceMapper、DTO（config/view/test）。
2. **凭据模块**：PasswordCipher + 配置项（local 默认密钥 + WARN）；单测覆盖加解密、篡改检测、错误密钥。
3. **方言模块**：SqlDialect 枚举 + limitOne 渲染；单测。
4. **连接池注册中心**：DataSourceRegistry（按 `租户::code` 懒建 HikariDataSource、刷新/逐出/关闭、@PreDestroy）。
5. **DynamicDatasourceService（query-exec）**：CRUD（密码加密/不回显）、在线测试（保存前/已保存两种）、池配置默认值。
6. **执行器改造**：QueryExecutor/QueryExecService 增加数据源参数重载（旧签名委托 null）；JdbcQueryExecutor 注入 registry，按编码取池，主库兜底；5 个生产调用点全部切换并透传 datasourceCode；比率指标同库校验；维度标量子查询改方言渲染。
7. **指标绑定透传**：BizMetric、MetricDetail、语义服务 CRUD/映射补 datasourceCode。
8. **管理 Controller（admin）**：pom 补依赖；DynamicDatasourceController 7 个端点 + 权限 + 4 个审计事件；DELETE 引用检查。
9. **前端**：admin.ts API；data/index.vue Tab 化 + registry 表格/Drawer/测试连接；MetricPanel 数据源选择与详情展示；类型补全。
10. **验证**：后端全量 `mvn test` + install；前端 vitest/vue-tsc/build；Playwright 回归 + 新增动态数据源临时全流程脚本（验收后删除）。

- ReportChartService：比率跨库拒绝、dialect 渲染断言。

**E2E（临时 Playwright，验收后删除脚本与 test-results）**：

## 12. 风险与对策

| 风险 | 等级 | 对策 |
| --- | --- | --- |
| 外部驱动增加打包体积/版本冲突 | 中 | P0 仅引入 mysql-connector-j、postgresql（版本走 Spring Boot BOM 管理），runtime scope |
| 生产密钥管理 | 高 | 启动 fail-fast；P2 接外部 KMS/Vault |
| 用户公式 SQL 与目标方言不兼容 | 中 | 文档明确"公式面向目标库书写"；错误信息透传执行器原始摘要；P1 做按方言校验 |
| 连接池泄漏（更新配置不关旧池） | 中 | 刷新路径先 close 后逐出；@PreDestroy 兜底；单测验证 |
| H2 内存库重启清空，注册的数据源丢失 | 低 | 与现有演示数据行为一致；后续接生产库即解决 |
| 执行期才发现数据源编码非法，写入期无约束 | 低 | 前端下拉约束；执行期错误文案明确；P1 可引入 SPI 接口做写入校验 |

## 13. 验收标准（P0）

1. 管理员可在 UI 完成 MySQL/PostgreSQL/H2 数据源的新建、测试、编辑、停用、删除；密码不明文回显；
2. 删除被指标引用的数据源被拒绝，错误文案明确；
3. 指标可绑定数据源；问数结论卡、图表（柱/折/饼）、明细表按绑定路由到目标库执行；不绑定的指标行为与现状完全一致；
4. 后端 `mvn test` 全模块绿；`mvn install -DskipTests -Djacoco.check.skip=true` 成功；
5. 前端 vitest 全量、vue-tsc、vite build 通过；Playwright 既有 4 个 e2e + 新增临时全流程全绿；
6. 临时脚本与 test-results 清理完毕；不提交 git，不新增除本方案外的文档。
