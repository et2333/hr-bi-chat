# 三功能模块开发方案：LLM 配置管理 / 用户与多租户管理 / C 端报表

> 后续修订：模型地址语义、发布后缓存失效、模拟部署状态、版本密钥处理及 Java/Python 问数链路，以《权限单一事实源与 Java/Python 问数链路收敛实施方案》为准。下文“mock 直接 ACTIVE”规则已废止。

## Context

S8（集成测试与质量门禁）已全绿：Java JaCoCo 门禁 + 596 tests、前端 Vitest 24 + Playwright E2E 3、pytest 40。在此基础上新增三个业务模块：

1. **LLM 配置管理**（管理台）：大模型参数可视化配置、版本管理、服务状态监控、一键部署，免手动编码、完整权限控制
2. **用户管理与多租户**：用户创建/角色分配/权限配置/密码重置/操作日志；租户隔离/资源配额/租户专属配置/生命周期
3. **C 端报表**：自定义报表生成、数据可视化（折线/柱状/饼图）、PDF/Excel 导出、定时推送

**用户已确认的决策**：
- 分阶段顺序实施（任务1→2→3），每阶段独立验证
- "一键部署" = 配置驱动模拟部署（参数持久化到 DB，部署=应用配置+健康检查+状态切换，不做真实 Docker）
- 多租户 = 在现有 SecOrgNode 组织树之上叠加 tenant 维度，复用 SecRole/SecOrgGrant/AuthzService
- 图表 = 前端 ECharts（已装 ^5.5.0）；导出 = Java OpenPDF（PDF）+ Apache POI（Excel）

**现有可复用基座**（已核实）：
- Python agent-gateway 已有 `/health`、`openai_client.py` 已参数化 base_url/api_key/model/temperature，`get_llm_adapter(LLM_PROFILE)` 工厂
- Java 侧 `application.yml` 有 `hrchat.ai.runtime`(local/remote) + `remote-base-url`，但 `KnowledgeConfig.java:66-73` 硬编码 `new LocalAgentRuntimeImpl(...)`
- 前端已有 `EChart.vue` 组件、echarts ^5.5.0 依赖
- hrchat-subscription 已有 `SubscriptionPushScheduler`（@Scheduled 60s）
- 功能授权已统一读取 `sec_role_permission`，由 `UserContext.functionPerms` 驱动后端裁决与前端菜单；`admin:*` 为可配置授权，不再由角色名称硬编码赋权。

## 总体架构

- **后端**：新增模块 `hrchat-model`（任务1，仿 hrchat-admin 结构）；任务2 扩展 hrchat-admin + 改造 hrchat-authz；任务3 扩展 hrchat-report/subscription
- **DB**：当前结构已固化为 Flyway baseline；后续 DDL 在 H2/MySQL 对应目录新增版本迁移，禁止回改 V1/V2
- **前端**：新增 `/admin/llm`、`/admin/users`、`/admin/tenants` 路由页；`/reports/:id` 内嵌 `ChartRenderer.vue`；`http.ts` 增加 `X-Tenant-No` 头（localStorage `hrchat_tenant_no` 默认 t01）
- **权限**：新权限码 `admin:llm:manage/view`、`admin:user:manage`、`admin:tenant:manage`、`admin:push:manage`，均挂 ADMIN 角色（`admin:*` 通配自动覆盖）

## 阶段 1：LLM 配置管理

**后端**：
- `LlmConfigService`：模型配置 CRUD（DB 单一事实源 + 内存缓存）、每次保存生成 version 快照、状态机
- `LlmDeployService`：`deploy` 端点执行"写 APPLYING → 调 Python `POST /v1/config`（base_url/api_key/model/temperature）→ 调 `/health` 验证（status=ok 且 profile/model 一致）→ ACTIVE + version 留痕；失败置 FAILED 可回滚上一版本"。local/test 的 mock 部署使用 `SIMULATED`，不进入真实远程路由。
- `LlmHealthService`：RestTemplate GET `{deploy_url}/health`（超时 2s），写 health_status/latency，失败置 DOWN
- **yml→DB 切换核心**：改造 `KnowledgeConfig.java` 的 `agentRuntimeClient` bean → `AgentRuntimeFactory`（ApplicationReadyEvent 加载 DB 中 state=ACTIVE 模型，有则构造新实现 `RemoteAgentRuntimeClient`（RestTemplate 调 Python），无则回退 `LocalAgentRuntimeImpl`；`hrchat.ai.runtime` yml 保留为兜底默认值，兼容旧配置）

**Python 侧**：`agent_gateway/app.py` 新增 `POST /v1/config` 与 `GET /v1/config/current`；`get_llm_adapter` 改可重建单例工厂

**前端** `/admin/llm`：模型列表（卡片+表格）、参数表单（apiKey password 类型+回显掩码）、版本列表（时间线+回滚）、监控面板（状态+延迟+最近检查）、"一键部署"（确认弹窗→轮询）

**端点**：`GET/POST/PATCH/DELETE /admin/llm/models`、`GET /admin/llm/models/{id}/versions`、`POST /admin/llm/models/{id}:deploy`、`POST /admin/llm/models/{id}:rollback`、`GET /admin/llm/models/{id}/health`、`GET /admin/llm/monitor`

## 阶段 2：用户管理与多租户

**用户管理**（扩展 hrchat-admin）：
- SecUser 无密码字段（SSO 镜像）→ 新增 `password_hash`（BCrypt）+ `must_change_pwd`；创建由后端生成随机初始密码**仅在创建响应返回一次明文**（标注"SSO 对接后废弃，当前仅演示"）；密码重置=重置随机密码+置 must_change_pwd=1；认证仍走 X-User-No mock
- 创建/角色分配（sec_user_role）/停用启用/逻辑删，全部记 AuditEvent（USER_CREATE/USER_ROLE_GRANT/PWD_RESET 等）

**多租户叠加**（改造 hrchat-authz + 全部业务 service）：
- 每租户在 sec_org_node 下挂子树（顶层节点 tenant_id 标记，org_path 物化路径不变）
- 请求链：`X-Tenant-No` 头 → `TenantContextHolder`（ThreadLocal）→ `UserContextService.resolve` 校验用户 tenant_id 与请求头一致
- **隔离改造点（影响面最大）**：① UserContextService.resolve 按 tenant_id 过滤 org 树/org_grant；② SqlRewriteService.buildOrgFilter 追加 `AND tenant_id = {ctx.tenantId}`；③ 业务列表查询（ReportService.list/listSnapshots/listSubscriptions、AdminDataService、AuditCollector 查询）一律 `WHERE tenant_id = ?`；④ Flyway V2 demo seed 种子归入 t01
- **兼容策略**：tenant_id 无默认值约束、未配置租户降级单租户视图，保证 S8 既有 596 测试大部分不改断言

**配额与生命周期**：ReportService.create/subscribe、UserService.create、订阅创建前查 `quotaUsed < quota`，超限抛新 ErrorCode.QUOTA_EXCEEDED；`GET /admin/tenants/{id}/usage`；tenant status 停用时 resolveContext 拒绝解析（FUNC_FORBIDDEN）

**端点**：`GET/POST /admin/users`、`PATCH /admin/users/{userId}`、`POST /admin/users/{userId}/roles`、`POST /admin/users/{userId}:reset-password`、`GET/POST /admin/tenants`、`PATCH /admin/tenants/{id}`、`POST /admin/tenants/{id}:disable/:enable`、`GET /admin/tenants/{id}/usage`

## 阶段 3：C 端报表

**图表渲染**：
- 新增 `ChartRenderer.vue`（props: chartType/option），内部按 line→折线/bar→柱状/pie→饼图归一化，统一 tooltip/dataZoom/legend；复用现有 `EChart.vue`
- `detail.vue` 按 rpt_component.chartType 渲染（现有映射 BAR/LINE/PIE/NUMBER_CARD 已支持）

**图表数据接口** `ReportChartService`：
- 解析 defJson {metric,dim,filter} → SemanticMetaService 取指标口径 → QueryExecService 经 AuthzService.rewriteSql（行级+tenant 隔离）执行 → 转 ECharts option：categories=dims、series=[{name,data}]（pie 转 {name,value}）
- 端点 `GET /reports/{id}/components/{compId}/chart-data`，权限 report:view + owner/share 校验沿用 ReportService.getDetail

**导出改造**（hrchat-report pom 增 `org.apache.poi:poi-ooxml:5.2.x`、`com.github.librepdf:openpdf:2.0.x`）：
- `ReportExcelExporter`：XSSFWorkbook（标题+水印行+表头+数据行）
- `ReportPdfExporter`：Document+Table，中文内置 STSong-Light 字体
- ReportExportService 改异步落 `rpt_export_task` 表（PENDING→COMPLETED），download 按 format 返回对应 media type；保留 BR-06 水印、≤5000 行、15min 有效期、导出审计
- 数据源统一走 ReportChartService 取数结果（图表数据=导出数据，口径一致）

**定时推送**：扩展 SubscriptionPushScheduler → SubscriptionPushService 生成快照+附件（PDF/Excel）→ LocalPushChannelClient 本地写文件/日志；`POST /admin/push:trigger` 手动触发（本地演示到点推送）

## 验证

- **阶段1**：LlmConfigService CRUD/状态机/回滚单测、AgentRuntimeFactory 两种装配断言（DB 无配置→Local、有 ACTIVE→Remote）、LlmHealthService mock RestTemplate；Python pytest（/v1/config 应用后 adapter 切换）；前端 Vitest（表单/版本时间线）+ Playwright（配置→部署→ACTIVE 全流程）；手动：部署后 Java 日志打印 remote URL
- **阶段2**：UserService CRUD/BCrypt 重置、同 SQL 在 t01/t02 下结果不同（隔离单测）、配额超限、停用租户拒绝解析；前端 Vitest + Playwright（用户 CRUD、切租户列表变化）；手动：两租户互不可见
- **阶段3**：ChartService 三种 chartType option 断言、Excel/PDF magic header 与行数断言、导出权限拒绝、调度器 mock 到期推送；前端 Vitest（ChartRenderer 归一化）+ Playwright（详情页图表、导出下载打开验证）
- **每阶段回归**：`mvn verify`（596 基线保底）+ 前端 `npm run test` + 新增测试纳入 JaCoCo 门禁

## 风险

- **租户隔离影响面最大**：必须先加列+t01 归属再逐服务改造，每改一个服务跑对应测试集（596 基线保底）
- **版本兼容**：POI 5.2.x 需 Java 17（项目已 17 ✓）；OpenPDF 2.0.x 无模块冲突；H2 BLOB 存导出文件可用（MODE=MySQL）
- **AI 配置迁移**：`hrchat.ai.runtime` 保留兜底，DB 未配置时行为与现在完全一致（LocalAgentRuntimeImpl），避免破坏 chat 全链路
- **密码形态**：明确"仅演示/SSO 后废弃"，避免误导为真实认证
- **顺序依赖**：任务3 导出数据接口依赖任务2 的 tenant 隔离（SQL 改写），严格按 1→2→3 顺序
