## 一、Quick BI 的六大能力板块

Quick BI 当前产品框架：**数据构建 → 数据分析 → 智能小Q → 数据消费 → 空间与权限 → 企业级能力**。核心卖点是"全场景数据消费"：50+ 数据源、Quick 加速引擎、仪表板/电子表格/数据大屏/数据门户四类作品、四大 AI Agent（问数/解读/报告/搭建）、多端+IM 消费。

## 二、对标矩阵

### 1. 数据接入与建模

| Quick BI 能力 | 状态 | 本项目现状 |
| --- | --- | --- |
| 数据源连接（50+ 引擎，在线测试/连接池管理） | 🟡 | 仅有数据源只读监控视图（data/index.vue），数据靠预置 H2 事实表，不能动态接库 |
| 本地 Excel/CSV 上传 | ❌ | 无上传入口、无文件解析 |
| 数据集建模（单表/多表 Join/自定义 SQL/数据集组合） | ❌ | 语义层是预置指标口径，不是可配置数据集模型 |
| 计算字段（函数表达式可视化配置） | ❌ | 指标公式硬编码在 Java SQL 模板中 |
| 层级维度（钻取目录配置） | 🟡 | 组织层级在面包屑中硬编码支持，不可配置 |
| Quick 加速引擎（抽取/列存/增量/缓存） | ❌ | 无 |
| 数据准备 ETL（0 代码节点编排） | ❌ | 无 |

### 2. 仪表板与可视化（差距最大的板块）

| 交叉表（透视、小计/总计样式） | ❌ | 只有平面明细表 |
| 组件联动（点击图表过滤其他组件） | ❌ | 无 |
| 全局查询控件（级联筛选、日期快捷范围） | 🟡 | 仅表格内单维度筛选下拉 |

| 问题收藏、智能选表确认 | ❌ | 无 |

| 小Q解读（仪表板整体解读+推荐问题） | 🟡 | 有图表级 AI 洞察，无仪表板级解读开关 |

| Agent 技能/MCP 生态 | 🟡 | 技术方案已设计 Milvus+MCP，落地为本地内存版 |

### 6. 权限、空间与企业级

| Quick BI 能力 | 状态 | 本项目现状 |
| --- | --- | --- |
| 工作空间（空间内作品协同隔离） | 🟡 | 多租户隔离更强但粒度是租户，无空间内协作 |
| 用户组 | ❌ | 有角色，无用户组树 |
| 行级权限 | ✅ | 空授权集拒绝、组织数据层级，执行得比较扎实 |
| 列级权限/字段脱敏 | 🟡 | 类型有 `masked` 标记、权限有 `fieldPolicies`，执行链路覆盖不完整 |
| 作品级细粒度权限（查看/编辑/导出/分享） | 🟡 | 仅导出有 BR-06 控制点，模型偏粗 |
| 审计日志 | ✅ | 敏感操作标记、多维查询完整 |
| 指标语义层管理 UI | ✅（P0 后更新） | 管理页面已建成：指标管理 / 维度管理 / 审批待办 / 同义词管理 4 个 Tab；支持指标新增/编辑/删除/启停、版本提交与审批通过/驳回、版本对比、引用血缘查看，维度删除与引用拦截；后端共 21 个接口（SemanticController 16 个，含审批待办列表；血缘 2 个；删除/启停 3 个） |
| 性能诊断工具 | ❌ | 无 |
| 信创兼容/等保认证 | ❌ | 未涉及 |
