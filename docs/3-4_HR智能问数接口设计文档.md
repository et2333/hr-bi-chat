## 1. 接口概述

### 1.1 接口目的

本文档定义 HR智能问数（HR ChatBI）系统全部对外及内部接口的契约，用于：

1. **开发依据**：作为前端（web-app / IM-H5）、Java 应用层、Python AI 运行时三方并行开发的统一契约，降低联调成本；
2. **测试依据**：作为契约测试（Pact）、接口自动化用例设计、性能压测脚本与安全越权用例的输入；
3. **治理基线**：作为接口变更评审、兼容性检查（oasdiff）与废弃流程的管控对象；
4. **集成依据**：作为与外部系统（企业SSO、IM平台、邮件网关）及内部中间件（Kafka）对接的边界契约。

### 1.2 适用范围

**接口通道范围**（与应用架构 V-06 接口清单一致）：

| 通道编号 | 通道 | 接口族 | 协议 | 调用方 → 提供方 | 本文档覆盖章节 |
|---|---|---|---|---|---|
| CH-1 | REST-BFF | `/api/v1/chat`、`/api/v1/reports`、`/api/v1/admin/*`、`/api/v1/exports` | HTTPS + JSON | web-app / IM-H5 → APISIX → 应用层 | 2.2 ~ 2.8 |
| CH-2 | 流式 | `/api/v1/chat/**`（SSE） | HTTPS + SSE | web-app → APISIX（透传）→ chat-service → agent-gateway | 2.2.5 ~ 2.2.7、2.2.11 |
| CH-3 | 跨栈工具 | MCP Tools（`semantic_query` 等 4 个） | JSON-RPC 2.0 over HTTP | agent-gateway（AI 运行时）→ mcp-server（Java） | 2.9 |
| CH-4 | 异步事件 | Kafka Topics（6 个） | JSON 事件 | 应用层 / AI 运行时内部 | 2.10 |
| CH-5 | 服务内 API | 模块间 API（OpenFeign） | REST（内网） | Java 模块之间 | 附录 A.3（仅清单，契约同 OpenAPI） |

**版本范围**：覆盖 V1.0（P0/P1）全部接口；V1.5（对比分析增强、报表中心增强）与 V2（归因分析）接口在文中以「版本」列标注，不阻塞 V1.0 开发。

**不适用**：APISIX 网关自身管理 API、K8s/中间件原生接口、数据集成层（DataX/Flink）任务配置界面——由各自平台自身管理。

**读者对象**：前端工程师、后端工程师、AI 算法工程师、测试工程师、SRE、安全审计人员。

### 1.3 术语定义

| 术语 | 定义 |
|---|---|
| BFF | Backend For Frontend，面向前端的聚合接入层，本系统由 APISIX + 应用层 REST 接口共同承担 |
| SSE | Server-Sent Events，服务端向浏览器单向推送事件的流式协议，本系统问答主链路的流式通道 |
| MCP | Model Context Protocol，AI 运行时调用 Java 能力（权限/语义查询等）的统一工具协议，JSON-RPC 2.0 over HTTP |
| OIDC | OpenID Connect，基于 OAuth 2.0 的身份认证协议，对接企业 SSO/IAM |
| JWT | JSON Web Token，本系统访问令牌格式，RS256 签名，有效期 ≤30 分钟 |
| 语义对象 | 语义层的元数据实体：指标（Metric）、维度（Dimension）、同义词（Synonym），Agent 取数入参只允许语义对象，禁止裸 SQL |
| 权限上下文 | 用户经 authz-service 裁决后的数据权限集合（组织范围 + 字段策略），随任务下发至 AI 运行时，缓存键含其指纹（BR-05） |
| 澄清反问 | 系统对歧义问句发起的多选式追问，通过 SSE `INTERRUPT` 事件承载（BR-07：单轮 ≤2 问、每问 ≤5 选项） |
| 口径 | 指标的业务定义、计算公式、统计周期与过滤条件，线上同一指标仅一个生效口径（BR-04） |
| 幂等键 | 写操作必带的 `X-Idempotency-Key` 请求头，服务端 24 小时窗口内去重 |
| trace_id | 全链路追踪标识，贯穿 web-app → Java → AI 运行时 → SQL，随响应头与错误体返回 |
| 三段式结果 | 答案的标准结构：结论层（数字卡/一句话）→ 数据层（明细表格）→ 图表层（可视化）+ 口径溯源 + 追问推荐 |
| 契约测试 | 基于 Pact/Spectral 的接口一致性自动化测试，CI 强制门禁 |

### 1.4 设计原则

| 编号 | 原则 | 说明 |
|---|---|---|
| P-1 | 资源化命名 | URI 使用名词复数（`/sessions/{id}/asks`）；动作型操作用 `:动作` 子资源（`POST /reports/{id}:subscribe`） |
| P-2 | 方法语义正确 | GET 幂等只读；POST 创建/动作；PATCH 部分更新；PUT 全量替换；DELETE 软删除 |
| P-3 | 无状态 | 服务端不保存客户端状态；会话状态集中于 Redis；SSE 断线靠 `Last-Event-ID` 恢复 |
| P-4 | 权限不旁路 | 所有数据访问接口经 authz-service 裁决；行级过滤在 SQL 生成阶段注入，禁止前端过滤（BR-02） |
| P-5 | 显式降级 | AI 异常时接口返回结构化降级标记（`degraded=true`），禁止静默降级 |
| P-6 | 契约先行 | 先契约后编码；OpenAPI YAML 入 Git，CI 执行 Spectral lint + Pact + oasdiff |
| P-7 | 中文友好 | `message` 使用中文自然语言；错误码与文案解耦；时间带时区；金额/比例字符串传输 |

## 2. 接口详细设计

### 2.1 通用设计约定

#### 2.1.1 Base URL 与环境

| 环境 | Base URL | 说明 |
|---|---|---|
| dev | `https://hrchat-dev.internal.example.com/api/v1` | 脱敏样本数据 |
| staging | `https://hrchat-staging.internal.example.com/api/v1` | 1:1 缩配，脱敏全量结构数据 |
| prod | `https://hrchat.internal.example.com/api/v1` | 生产 |

MCP 通道 Base URL：`http://mcp-server.hrchat-ai.svc.cluster.local/mcp`（仅 K8s 内网可达，D-2 网络策略保证不对外暴露）。

#### 2.1.2 通用请求头

| 请求头 | 必填 | 约束 | 说明 |
|---|---|---|---|
| `Authorization` | 是 | `Bearer {JWT}` | OIDC 访问令牌，RS256 签名，exp ≤ 30min；除外：健康检查 |
| `Content-Type` | 是 | `application/json; charset=utf-8` | 有请求体的接口必带 |
| `Accept` | 否 | `application/json` / `text/event-stream` | 问答接口默认 `text/event-stream` |
| `X-Idempotency-Key` | 写操作必带 | UUID v4 | 服务端 24h 去重；重复提交返回首次结果 |
| `X-Request-Id` | 否 | 客户端生成 UUID | 缺失时网关生成；响应头原样返回 |
| `Last-Event-ID` | SSE 重连时 | 上次收到的最大 `seq` | 服务端从 Redis 事件窗口（5 分钟）回放 |
| `Accept-Language` | 否 | 默认 `zh-CN` | 当前仅支持中文文案 |

通用响应头：`X-Trace-Id`（全链路追踪）、`X-Request-Id`（回显）、限流接口附 `X-RateLimit-Limit / X-RateLimit-Remaining / X-RateLimit-Reset`。

#### 2.1.3 通用响应结构

**成功响应**：HTTP 2xx，响应体直接为业务数据对象（不二次包裹）；分页响应统一结构：

```json
{
  "items": [],
  "page": 1,
  "size": 20,
  "total": 135
}
```

**错误响应**：HTTP 4xx/5xx，统一错误模型（见 6.1）：

```json
{
  "code": "HRC-2003",
  "message": "您暂无销售部数据的查看权限，请联系管理员",
  "trace_id": "tr-9f2c1a77e4",
  "details": [{"field": "org_id", "issue": "out_of_scope"}]
}
```

#### 2.1.4 分页、排序与筛选约定

| 项 | 约定 |
|---|---|
| 分页参数 | `page`（默认 1，≥1）、`size`（默认 20，≤200） |
| 排序参数 | `sort=field`（升序）/ `sort=-field`（降序），多字段逗号分隔，如 `sort=-updated_at,created_at` |
| 筛选参数 | 平铺于 query string，如 `?status=COMPLETED&domain=STAFF&keyword=离职` |
| 时间筛选 | `start_time` / `end_time`，ISO-8601 带时区，左闭右开 `[start, end)` |
| 大小写 | 枚举值统一大写下划线（`COMPLETED`）；关键词筛选不区分大小写 |

#### 2.1.5 幂等性约定

| 场景 | 机制 |
|---|---|
| 创建类（POST） | 必带 `X-Idempotency-Key`；服务端按 `key + 接口 + 用户` 24h 去重；重复请求返回首次结果与 `X-Idempotent-Replay: true` 响应头 |
| 更新类（PATCH/PUT） | 天然幂等（最终态语义）；可选带 `If-Match`（资源 `version`）做乐观锁，冲突返回 409 |
| 删除类（DELETE） | 幂等；删除不存在资源返回 204 |
| 问答提交 | 幂等键防重复扣费/重复执行；同会话同问句不同幂等键视为新提问 |

#### 2.1.6 数据类型与格式约定

| 类型 | 格式 | 示例 |
|---|---|---|
| 时间戳 | ISO-8601 带时区 | `2026-09-13T10:00:00+08:00` |
| 日期 | `YYYY-MM-DD` | `2026-09-13` |
| 月份 | `YYYY-MM` | `2026-09` |
| 金额 | 字符串传输防精度丢失，字段名带单位后缀 | `"amount_cny": "123456.78"` |
| 比例/百分比 | 字符串数值，`unit` 字段标注单位 | `"value": "12.5", "unit": "PERCENT"` |
| ID | 字符串，带类型前缀 | `sess_a1b2c3`、`ask_d4e5f6`、`rpt_g7h8i9`、`mtc_j0k1l2`、`exp_m3n4o5` |
| 布尔 | `true` / `false` | |
| 枚举 | 大写下划线 | `PLAN_TYPE.MONTHLY` |
| 空值 | 统一 `null`，禁止省略字段或空字符串表达 null | |

#### 2.1.7 HTTP 状态码定义

| 状态码 | 语义 | 使用场景 |
|---|---|---|
| 200 OK | 成功 | GET 查询；POST 动作类（订阅应答、反馈）；SSE 流建立成功 |
| 201 Created | 创建成功 | 创建会话/报表/指标/角色等资源类 POST |
| 202 Accepted | 已受理（异步） | 问句转后台执行确认、导出任务受理、评测任务触发 |
| 204 No Content | 成功无返回体 | DELETE、部分动作类 POST（反馈） |
| 400 Bad Request | 参数错误 | 参数缺失/类型错误/取值非法（HRX-1xxx） |
| 401 Unauthorized | 未认证 | Token 缺失/过期/验签失败（HRC-2001） |
| 403 Forbidden | 已认证但无权限 | 接口功能权限、数据范围权限、字段权限拦截（HRC-2xxx） |
| 404 Not Found | 资源不存在 | ID 无效或越权访问他人资源（不暴露存在性，统一 404） |
| 409 Conflict | 冲突 | 幂等键冲突未完成、乐观锁版本冲突、重名资源 |
| 429 Too Many Requests | 限流 | 超出用户级/全局限流阈值（HRS-3003） |
| 500 Internal Server Error | 系统错误 | 服务端异常（HRS-3xxx） |
| 503 Service Unavailable | 服务降级/不可用 | AI 服务降级模板直查时仍返回 200+`degraded`；仅整体不可用时 503（HRS-3002） |

> **SSE 特例**：SSE 流建立后（HTTP 200）发生错误，不再变更 HTTP 状态码，改发 `ERROR` 事件后关闭流（见 2.2.11）。

### 2.2 智能问数接口（chat-service）

#### 2.2.1 创建会话

| 项 | 内容 |
|---|---|
| 接口 | `POST /api/v1/chat/sessions` |
| 功能 | 创建对话会话（FR-03 多轮对话的载体）；会话超 30 分钟无交互自动过期（BR-08） |
| 权限点 | `chat:ask` |

**请求参数**：

| 参数 | 位置 | 类型 | 必填 | 约束 | 说明 |
|---|---|---|---|---|---|
| title | body | string | 否 | ≤50 字符 | 会话标题，缺省取首个问句前 20 字 |
| source | body | string | 是 | `WEB` / `IM_H5` | 会话来源渠道 |

**响应**（201）：

```json
{
  "session_id": "sess_a1b2c3",
  "title": null,
  "source": "WEB",
  "status": "ACTIVE",
  "created_at": "2026-09-13T10:00:00+08:00",
  "expires_at": "2026-09-13T10:30:00+08:00"
}
```

#### 2.2.2 会话列表

`GET /api/v1/chat/sessions?page=1&size=20&sort=-updated_at&keyword=离职`

**响应**（200）：分页结构，`items[]` 元素含 `session_id / title / updated_at / ask_count`。仅返回当前用户自己的会话。

#### 2.2.3 会话详情（含历史问答）

`GET /api/v1/chat/sessions/{sessionId}`

**响应**（200）：

```json
{
  "session_id": "sess_a1b2c3",
  "title": "入职与离职查询",
  "status": "ACTIVE",
  "asks": [
    {
      "ask_id": "ask_d4e5f6",
      "question": "上月入职了多少人",
      "status": "COMPLETED",
      "answer_id": "ans_z9y8x7",
      "conclusion_brief": "上月入职128人，环比+12%",
      "created_at": "2026-09-13T10:01:00+08:00"
    }
  ],
  "created_at": "2026-09-13T10:00:00+08:00",
  "expires_at": "2026-09-13T10:30:00+08:00"
}
```

> `conclusion_brief` 为列表页摘要；完整三段式结果通过 `GET /api/v1/chat/asks/{askId}` 获取。历史结果按「用户+权限上下文」隔离，权限变更后旧答案重新打开时服务端重校验（BR-05）。

#### 2.2.4 更新会话 / 删除会话

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/v1/chat/sessions/{sessionId}` | PATCH | 重命名（`{"title": "..."}`）；软删前的元数据更新 |
| `/api/v1/chat/sessions/{sessionId}` | DELETE | 软删除，90 天后物理清理（数据生命周期见架构 V-04） |

#### 2.2.5 提交问句（核心接口，SSE 流式）

| 项 | 内容 |
|---|---|
| 接口 | `POST /api/v1/chat/sessions/{sessionId}/asks` |
| 功能 | 提交自然语言问句，返回 SSE 事件流（意图识别→语义解析→权限改写→执行→归纳生成的过程与结果）；FR-01/02/03/04 |
| 请求头 | `Accept: text/event-stream`（默认）；`X-Idempotency-Key` 必带 |
| 权限点 | `chat:ask` |
| 降级 | AI 服务不可用时走 Top200 模板直查，`ANSWER_DONE.payload.degraded=true` 并附提示文案（FR-24） |

**请求参数**：

| 参数 | 位置 | 类型 | 必填 | 约束 | 说明 |
|---|---|---|---|---|---|
| question | body | string | 是 | 1~500 字符 | 自然语言问句 |
| mode | body | string | 否 | `STREAM`（默认）/ `SYNC` | `SYNC` 时 `Accept: application/json`，同步返回完整答案（IM-H5 轻量场景与降级兜底用） |
| context_override | body | object | 否 | — | 显式覆盖继承的上下文（下钻/切换维度），字段见下 |

**context_override 定义**：

| 参数 | 类型 | 说明 |
|---|---|---|
| time_range.preset | string | 时间预设：`LAST_7D / LAST_30D / THIS_MONTH / LAST_MONTH / THIS_QUARTER / LAST_QUARTER / THIS_YEAR / LAST_YEAR / CUSTOM` |
| time_range.start / end | string | `CUSTOM` 时必填，ISO-8601 |
| time_range.grain | string | 时间粒度：`NONE / DAY / WEEK / MONTH / QUARTER / YEAR` |
| org.org_id | string | 组织节点 ID |
| org.include_children | boolean | 是否含下级，默认 `true` |
| metrics | string[] | 显式指定指标语义对象（问答下钻传参用） |

**响应**（200，`Content-Type: text/event-stream`）：事件流，事件类型与载荷见 2.2.11。`mode=SYNC` 时响应体为 `ANSWER_DONE.payload` 的完整 JSON。

**关键约束**：

| 约束 | 规则 |
|---|---|
| 流内超时 | 执行超 30s 转后台异步：流内发 `ANSWER_DONE.payload.status=ASYNC_RUNNING` 并收流，任务完成后 IM/站内推送（PRD FR-01 异常流） |
| 澄清 | 歧义问句发 `INTERRUPT` 事件（类型 `CLARIFY`）并暂停，等待 2.2.6 应答后续流 |
| 无权限 | 数据范围外问句发 `ERROR` 事件（`HRC-2003`）并记审计（BR-02） |
| 心跳 | 每 15s 一个 `HEARTBEAT` 事件防代理断连 |
| 断线恢复 | 客户端带 `Last-Event-ID` 重连，服务端从 Redis 回放窗口（5 分钟）续传 |

#### 2.2.6 澄清应答

| 项 | 内容 |
|---|---|
| 接口 | `POST /api/v1/chat/sessions/{sessionId}/asks/{askId}/clarifications` |
| 功能 | 对 `INTERRUPT`（CLARIFY）事件的选项应答，服务后继续原问答流（FR-02） |
| 请求头 | `Accept: text/event-stream`；`X-Idempotency-Key` 必带 |
| 权限点 | `chat:ask` |

**请求参数**：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| answers[].question_id | string | 是 | 对应 `INTERRUPT` 载荷中的 `question_id` |

#### 2.2.11 SSE 事件规范（问答 / 归因统一）

事件帧格式：

```text
event: ANSWER_DONE
data: {"seq": 12, "event": "ANSWER_DONE", "ts": "2026-09-13T10:01:02+08:00", "payload": {…}}
```

| 规则 | 说明 |
|---|---|
| `seq` | 会话内单调递增整数，客户端乱序缓冲重排 |
| `ts` | ISO-8601 带时区 |
| 心跳 | `HEARTBEAT` 每 15s，`seq` 不占用（固定 `-1`） |
| 回放 | `Last-Event-ID` 触发 Redis 窗口回放（5 分钟），窗口外返回 409 + `HRS-3004`，客户端转 2.2.7 拉取 |

**事件类型与载荷 Schema**：

| 事件类型 | 触发时机 | payload 关键字段 | 前端表现 |
|---|---|---|---|
| `MESSAGE_DELTA` | 结论摘要流式生成 | `delta`（增量文本）、`phase`（`PARSING/SUMMARIZING`） | 骨架屏→逐字渲染 |
| `INTERRUPT` | 歧义澄清（BR-07：≤2 问、每问 ≤5 选项） | `interrupt_type`（`CLARIFY`）、`ask_id`、`questions[{question_id, question, options[{option_id, label}], multiple}]` | 澄清选项卡 |
| `PLAN_UPDATE` | 归因任务计划更新 | `steps[{step_id, title, status}]` | 「分析计划」清单逐项打勾 |
| `TOOL_CALL_START` | 工具调用开始 | `tool`、`summary` | 「正在查询研发中心离职率…」 |
| `TOOL_CALL_END` | 工具调用结束 | `tool`、`ms`、`rows` | 进度完成态 |
| `ANSWER_DONE` | 答案完成（终态） | 完整三段式结构，见下 | 渲染答案卡 |
| `ERROR` | 流内错误（终态） | `code`、`message`、`recoverable`（`true`=可重试） | 错误卡+重试按钮 |
| `HEARTBEAT` | 保活 | 空 | 无 |

**`ANSWER_DONE.payload` 完整结构（三段式，FR-04）**：

| 字段 | 类型 | 说明 |
|---|---|---|
| ask_id / answer_id | string | 问句与答案 ID |
| status | string | `COMPLETED / ASYNC_RUNNING` |
| intent | string | `QUERY / ANALYSIS / OPERATION / CHITCHAT` |
| degraded | boolean | 是否降级模板直查（FR-24），`true` 时附 `degraded_tip` |
| conclusion | object | 结论层：`type`（`NUMBER_CARD/TEXT`）、`value`、`unit`、`compare{period, value, direction}` |
| table | object | 数据层：`columns[{key, name, type, masked}]`、`rows[]`（≤20 条）、`total`、`page`、`size`；脱敏字段 `masked=true` |
| chart | object | 图表层：`type`（`NUMBER_CARD/LINE/AREA/BAR/BAR_H/PIE/DONUT/SCATTER/COMBO/HEATMAP/BULLET`）、`recommended`、`config`（ECharts option 子集） |
| caliber | object | 口径溯源：`metric / definition / time_range / data_updated_at`（BR-09 数据时效标注） |
| followups | string[] | 追问推荐（≤3 条） |
| elapsed_ms | integer | 端到端耗时 |

> 明细表格超过 20 条的分页拉取：`GET /api/v1/chat/asks/{askId}/table?page=2&size=20&sort=-hire_cnt`，响应结构同 `table` 字段（权限上下文校验后返回）。

### 2.9 MCP 工具接口（跨栈：AI 运行时 → Java `/mcp`）

**协议**：JSON-RPC 2.0 over HTTP，单端点 `POST /mcp`，方法 `tools/list` / `tools/call`。**仅内网可达**（生产配合 NetworkPolicy；D-2）。机读契约以 `hrchat-deploy/schemas/mcp/` 为准。

**两层认证（现行）**：

| 层 | 凭证 | 含义 |
|---|---|---|
| 服务身份 | 请求头 `X-Service-Token` | 证明调用方是允许访问 MCP 的 Python agent-gateway（或等价服务） |
| 任务绑定 | `params.context.tool_context_token` | Java 在本次问数进入运行时前签发的短期 HS256 JWT；载荷仅含 `sub=empNo`、`tenant_id`、`invocation_id`、`jti`、`iat/exp` 等，**不携带**角色/组织范围/字段策略 |

Python **只转交**工具令牌，不得自报权限。Java 校验服务令牌与工具令牌（含 `invocation_id` 绑定）后，按 `empNo` **重新装配**当前 `UserContext`，再执行改写与取数（红线：权限不旁路，ADR-007 / 1001 方案）。

> **历史决策备注（已废止）**：早期接口稿曾写「UserContext / 浏览器 JWT 随任务由 agent-gateway 透传」。该方案与「应用层不透传用户 JWT、MCP 不信任 AI 自报权限」冲突，且易导致权限快照旁路。已收敛为上表两层凭证；实现与评审均以工具令牌为准，勿再按透传 JWT 实现新链路。

**本期工具**：`get_semantic_meta`、`permission_check`、`semantic_query` 已实现；`report_save` 仍保留目标契约，**本期未接入** Python 编排。

**通用请求结构**（`tools/call`）：

```json
{
  "jsonrpc": "2.0",
  "id": "req-001",
  "method": "tools/call",
  "params": {
    "name": "semantic_query",
    "arguments": { "…": "见各工具定义" },
    "context": {
      "trace_id": "tr-9f2c1a77e4",
      "tool_context_token": "<Java 签发的短期 JWT>",
      "invocation_id": "inv-…",
      "tool_call_id": "tc_…"
    }
  }
}
```

**通用错误**：JSON-RPC `error.code` 为 `-32000`（及协议级 `-3260x`），`error.data` 携带业务错误模型（`code`/`message`/`retryable`，同 6.1）。权限拒绝不可重试；传输/5xx 可由客户端对同一 `tool_call_id` 重试 1 次。

#### 2.9.1 semantic_query（语义取数，唯一取数入口）

| 项 | 内容 |
|---|---|
| arguments | `metrics[]`（必填）、`time_range{preset?, start?, end?, grain?}`、`org_context{org_id, include_children}`、`limit`（服务端封顶，当前默认 ≤200） |
| 本期限制 | `dimensions` / `filters` **暂不支持**：若传入且非空则返回参数错误；禁止 `sql` / 数据源 / JDBC 等物理覆盖字段 |
| 服务端行为 | 按工具令牌重建用户 → 语义模板拼 SQL → authz 改写（组织过滤）→ 只读执行 → 字段策略（指标列明文，PII 按策略脱敏） |
| `org_context` | 仅表示用户希望查询的组织；越权直接 `HRC-2003`，绝不扩大授权范围 |
| result | `{columns[{key, name, type, masked}], rows[], caliber_meta{metric, definition, version}, permission_rewrite_applied: true, row_count}` |
| 性能 | 目标 P95 < 800ms（含数仓执行；本地 H2 演示不作为 SLA） |

#### 2.9.2 permission_check（权限预检）

| 项 | 内容 |
|---|---|
| arguments | `semantic_objects[]`（如 `metric:salary_total`）、`intent`（`QUERY/EXPORT`） |
| result | `{allowed, field_policies[{field, policy}], org_scope{org_paths[]}, reason?}` |
| 说明 | 预检结果不可复用为 `semantic_query` 授权；每次查询仍以最新 `UserContext` 裁决 |

#### 2.9.3 report_save（报表保存，本期未实现）

| 项 | 内容 |
|---|---|
| arguments | `name`、`source_ask_id`、`components{}` |
| result | `{report_id}`；校验发起人 `report:create` 权限 |
| 状态 | 接口目标保留；Python / MCP handler **尚未接入**，调用应得到明确未实现或等价错误 |

#### 2.9.4 get_semantic_meta（语义元数据查询）

| 项 | 内容 |
|---|---|
| arguments | `type`（`METRIC/DIMENSION/SYNONYM`）、`names[]`（可空，空则按类型列举可见对象） |
| result | `{objects[{code, name, definition, formula?, available_dimensions[], version, …}]}` |
| 说明 | 仅返回已发布/可见语义对象；禁止返回密钥或物理库凭证 |

| Topic | 生产者 → 消费者 | 载荷关键字段 | 用途 |
|---|---|---|---|

## 3. 接口安全策略

### 3.1 认证方式

| 项 | 方案 |
|---|---|
| 用户认证 | 企业 SSO（IAM）OIDC，Authorization Code + PKCE；禁止本系统本地口令登录 |
| 访问令牌 | JWT（RS256 非对称签名），`exp ≤ 30min`；APISIX 基于 JWKS 内网端点前置验签，无效/过期一律 401（HRC-2001），不透传到应用层 |
| 刷新令牌 | Refresh Token 轮换（Rotation），单次有效；被重放时全家吊销 |
| 会话管理 | 闲置 30 分钟过期；SSO 断连时拒绝新登录、已登录会话保活 ≤2h（架构 V-01） |
| 服务间认证 | Java ↔ agent-gateway：问数请求携带 `tool_context_token` / `invocation_id` / `trace_id`（非浏览器 JWT 透传）；MCP：`X-Service-Token` + `tool_context_token`，生产配合 NetworkPolicy；mTLS 可选加固 |
| 防重放 | JWT `exp` + `jti` 去重窗口 5 分钟 |

### 3.2 授权机制

**三层权限模型**（PRD FR-17/18/19）：

| 层 | 对象 | 执行点 |
|---|---|---|
| 功能权限（RBAC） | 接口权限点（见 3.2.2） | APISIX 路由级粗粒度 + 应用层注解级细粒度 |
| 数据范围（行级） | 组织节点（含下级） | authz-svc 在 SQL 生成阶段注入 `org_path IN (...)`（BR-02，禁止前端过滤） |
| 字段策略（列级） | 敏感字段脱敏/隐藏/明文 | SQL 列裁剪 + Doris 动态脱敏函数双保险；明文查看需审批 + 审计（BR-03） |

**授权裁决规则**：接口先验功能权限（403/HRC-2002），数据链路再验范围与字段（403/HRC-2003、2004）；两者都通过才放行。问答结果缓存键含权限上下文指纹，禁止跨用户复用（BR-05）。

**3.2.2 接口权限点映射表**（节选，全量见 OpenAPI `security` 定义）：

| 接口组 | 权限点 | 默认授权角色 |
|---|---|---|
| 问答提交/澄清/反馈 | `chat:ask` | 全部 HR 用户 |
| 查看SQL | `chat:view_sql` | 数据管理员、审计 |
| 归因分析 | `chat:attribution` | HRD 及以上（V2） |
| 报表读/建/管 | `report:read / report:create / report:manage` | 全员 / 全员 / 所有者 |
| 订阅 | `report:subscribe` | 全员 |
| 导出 | `export:apply` | 需单独授权（BR-06） |
| 语义层配置/审批 | `admin:semantic:manage / admin:semantic:approve` | 数据管理员 / HR数据负责人 |
| 权限管理 | `admin:authz:manage` | 系统管理员（敏感授权双人审批） |
| 审计检索 | `admin:audit:read` | 审计角色、系统管理员 |
| 同步监控/重试 | `admin:data:read / admin:data:manage` | 数据管理员 |
| 评测管理 | `admin:eval:manage` | 数据管理员、测试 |
| 租户生命周期管理 | `admin:tenant:manage` | 平台系统管理员 |
| 本租户用户/LLM管理 | `admin:user:manage / admin:llm:manage` | 平台系统管理员、租户管理员（仅本租户） |
| 跨租户支持切换 | `admin:tenant:switch` | 仅平台系统管理员；必须指定目标租户、填写原因并记录审计，且不绕过字段/数据范围权限 |

### 3.3 数据加密要求

| 环节 | 要求 |
|---|---|
| 传输加密 | 全站 TLS 1.2+（生产建议 1.3），HSTS 开启；禁止任何 HTTP 明文端口对外 |
| 存储加密 | L3 敏感字段（薪酬明细/证件号/银行卡）AES-256 或 SM4 字段级加密；密钥 Vault/Sealed Secrets 管理，禁止明文入 Git 与配置 |
| 报表快照/导出文件 | MinIO 服务端加密（SSE-S3）+ 访问用短时效预签名 URL（15 分钟） |
| 日志脱敏 | L3 字段值禁止入日志/审计明文（采集侧脱敏，仅存摘要）；错误 `message` 不得回显敏感参数 |
| 导出文件 | 内嵌水印（用户名+工号+时间），BR-06 |
| JWT | 仅携带 `sub/roles/org_scope_fingerprint`，**不携带**薪酬等敏感声明 |

### 3.4 接口级防护

| 防护 | 策略 |
|---|---|
| 限流 | 用户级：问答 10 次/分钟、导出 5 次/天、管理接口 60 次/分钟；SSE 并发连接 ≤3/用户；全局设计容量 100 QPS；超限 429（HRS-3003）+ `Retry-After` |
| 输入校验 | 问句 ≤500 字符；分页 `size ≤ 200`；排序/筛选字段白名单；SQL 注入与越权参数在 L2 应用层清洗（架构 V-07） |
| 只读红线 | query-exec 仅放行 SELECT，DDL/DML/DCL 一律拦截（BR-01）；SQL 白名单校验失败记审计 |
| 越权检测 | IDOR：资源属主校验，非本人资源统一 404 不泄露存在性；越权拦截激增触发 P0 告警 |
| 审计留痕 | 全部接口访问留审计；敏感操作（导出/明文查看/权限变更）单独标记，≥3 年（BR-11） |

### 5.1 版本控制策略

| 项 | 策略 |
|---|---|
| 版本位置 | URI 主版本：`/api/v1/**`、`/mcp`（MCP 工具以 `name`+`version` 字段管理）、Kafka Topic 不带版本（Schema Registry 管理） |
| 当前版本 | v1 |

| 版本共存 | v1/v2 并行期间路由隔离；数据双向兼容（v1 创建的资源 v2 可读） |

### 5.2 变更分类与兼容性规则

| 变更类型 | 示例 | 是否破坏性 | 处理方式 |
|---|---|---|---|
| 新增接口 | 新增 `GET /api/v1/chat/asks/{id}/table` | 否 | 直接合入 |
| 新增可选请求参数 / 可选响应字段 | `asks` 新增可选 `context_override.org` | 否 | 直接合入（客户端忽略未知字段） |
| 新增枚举值 | 图表类型新增 `WATERFALL` | 视情况 | 前端确认默认渲染兜底后合入 |
| 新增 SSE 事件类型 | 新增 `PROGRESS` 事件 | 否 | 前端按未知事件忽略 |
| 修改字段语义/类型 | `value` 由 number 改 string | **是** | 禁止在 v1 内做；升 v2 |
| 删除字段/参数/接口 | 下线 `GET /sql` | **是** | 走废弃流程（5.4）后升 v2 |
| 必填性变更（选→必） | 某可选参数变必填 | **是** | 升 v2 |
| 错误码 | 只增不改义；已发布错误码语义冻结 | — | 新增走 MR 评审 |

### 5.3 变更流程与契约治理

```
接口变更 MR（OpenAPI YAML / SSE Schema / MCP 契约 / Kafka Schema 四件套）
  → CI：Spectral lint（0 error 门禁）
  → CI：oasdiff 破坏性变更检测（识别为破坏性 → 自动打标 + 架构评审）
  → CI：Pact 契约测试（provider 验证，前后端双向）
  → 评审：变更方 + 受影响消费方（web-app / agent-gateway / mcp-server）会签
  → 合入 main → 本文档同一 MR 内同步修订 → 契约版本 tag 发布
```

- **单一事实源**：契约文件集中于 `hrchat-deploy` 仓库（架构 V-11 14.1），禁止口头契约、禁止仅改文档不改契约。
- **紧急变更**：生产热修可先行，24h 内补齐契约 MR 与评审（对齐紧急变更流程）。
- **Kafka Schema**：注册表兼容性 `BACKWARD`，不兼容需新 Topic 或版本化 Schema。

### 5.4 废弃（Deprecation）流程

1. **公告期 ≥90 天**：变更公告 + 消费方通知（IM/邮件）；接口响应头加 `Deprecation: true` 与 `Sunset: <HTTP-date>`（RFC 8594）。
2. **过渡监控**：按消费方统计废弃接口调用量，归零后进入下线窗口。
3. **下线执行**：返回 410 Gone（`HRS-3005`）一个版本周期后物理移除；v1 整体下线前发布迁移指南（v1→v2 字段映射表）。

## 6. 错误处理机制

### 6.1 统一错误响应模型

```json
{
  "code": "HRC-2003",
  "message": "您暂无销售部数据的查看权限，请联系管理员",
  "trace_id": "tr-9f2c1a77e4",
  "details": [{"field": "org_id", "issue": "out_of_scope"}]
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| code | string | 业务错误码，`HR<域>-<序号>` 五段式（见 6.2），与 HTTP 状态码一对多映射 |
| message | string | 中文自然语言描述，可直接展示给用户；禁止暴露堆栈/SQL/内部路径 |
| trace_id | string | 全链路追踪 ID，用户报障与排障凭据 |
| details | array | 可选；结构化错误明细（字段级校验错误等），无则为 `[]` |

### 6.2 错误码分段定义（与架构 V-06 一致）

| 分段 | 域 | HTTP 映射 | 说明 |
|---|---|---|---|
| `HRX-1xxx` | 参数错误 | 400 / 409 | 请求参数校验类 |
| `HRC-2xxx` | 权限错误 | 401 / 403 / 404 | 认证、授权、数据范围、字段脱敏 |
| `HRS-3xxx` | 系统错误 | 429 / 500 / 503 | 服务端异常、限流、降级 |
| `HRA-4xxx` | AI 能力错误 | 200+ERROR事件 / 500 / 503 | 意图识别、NL2SQL、Agent 预算熔断 |
| `HRD-5xxx` | 数据错误 | 200（带标注）/ 500 / 504 | 查询超时、同步延迟、质量校验 |

### 6.3 错误码清单（核心）

| 错误码 | HTTP | message 模板 | 客户端处理 |
|---|---|---|---|
| HRX-1001 | 400 | 参数缺失：{field} | 表单校验提示 |
| HRX-1002 | 400 | 参数类型错误：{field} | 表单校验提示 |

| HRX-1004 | 400 | 分页参数越界（size≤200） | 自动回退默认值重试 |
| HRX-1005 | 400 | 问句长度超限（≤500字符） | 前端截断提示 |
| HRX-1006 | 409 | 幂等请求处理中，请勿重复提交 | 静默等待首次结果 |
| HRC-2001 | 401 | 登录已过期，请重新登录 | 跳转 SSO 重新认证 |
| HRC-2002 | 403 | 您暂无该功能的访问权限 | 展示无权限页 |
| HRC-2003 | 403 | 您暂无{org}数据的查看权限，请联系管理员 | 数据范围提示（记审计） |
| HRC-2004 | 403 | 字段「{field}」需明文查看授权（申请入口） | 引导发起授权申请 |
| HRC-2005 | 403 | 导出未授权或超出限制（≤5000行/5次日） | 提示申请导出权限 |
| HRS-3001 | 500 | 系统繁忙，请稍后重试 | 指数退避重试（≤2次） |
| HRS-3002 | 503 | 服务暂不可用（{降级级别}） | 按降级提示渲染 |
| HRS-3003 | 429 | 请求过于频繁，请{Retry-After}秒后重试 | 读 `Retry-After` 退避 |
| HRS-3004 | 409 | SSE 回放窗口已过期（5分钟） | 转全量拉取 `GET /asks/{id}` |
| HRS-3005 | 410 | 接口已下线，请升级客户端 | 提示刷新版本 |
| HRA-4001 | 200+ERROR | 未能理解您的问题，换个说法试试？ | 兜底话术+示例问句+转人工 |
| HRA-4002 | 200+ERROR | 问题解析失败：{原因摘要} | 建议澄清或简化问句 |
| HRA-4003 | 200+ERROR | 查询超时，已转后台执行，完成后将通知您 | 切异步态轮询/等推送 |
| HRA-4004 | — | （不报错）智能解析暂不可用，已返回预设查询 | 前端降级提示条（`degraded=true`） |
| HRA-4005 | 200+ERROR | 分析预算已达上限，已返回基础对比结果 | 渲染基础归因卡 |
| HRA-4006 | 200+ERROR | 组织无法识别，或暂不支持该查询条件；具体原因见 message | 展示提示并停止，不生成答案卡、不改查汇总；recoverable=false |
| HRD-5001 | 200+ERROR | 数据查询超时，请缩小时间范围后重试 | 引导缩小范围 |
| HRD-5002 | — | （不报错）空结果正常返回 200 空集 | 空态引导 |
| HRD-5003 | — | （不报错）答案标注「数据可能延迟，更新至{date}」 | 时效标注渲染（BR-09） |

> **设计原则**：空结果、数据延迟、AI 降级均为**正常业务态**，HTTP 200 + 结构化标注表达；错误码只描述异常，避免滥用 4xx/5xx 表达业务状态。

### 6.4 SSE 流内错误与客户端处理指引

| 场景 | 表现 | 客户端动作 |
|---|---|---|
| 流建立前失败 | 标准 4xx/5xx JSON | 按错误码处理 |
| 流内可恢复错误 | `ERROR` 事件，`recoverable=true` | 提供重试按钮，重试复用幂等键 |
| 流内不可恢复错误 | `ERROR` 事件，`recoverable=false` | 渲染错误卡，关闭流 |
| 网络断连 | 连接中断 | 自动重连（`Last-Event-ID`，退避 1s/2s/5s，≤5 次）；窗口过期转拉取 |
| 客户端通用重试 | 5xx/HRS-3001 | 指数退避（1s/2s/4s）重试 ≤2 次；4xx 不重试；写操作重试必复用幂等键 |

## 8. 接口测试要求

### 8.1 测试环境

| 环境 | 数据 | 用途 | 接口测试特殊配置 |
|---|---|---|---|
| dev | 脱敏样本数据（≈1 万人员规模模拟） | 开发自测、联调 | SSO Mock、IM 通道 Mock、vLLM 降配 14B |

**环境前置**：每环境提供独立 `Base URL`、测试账号组（HRBP/HRD/CHO/管理员/审计 五类角色 + 越权专用账号）、OpenAPI 契约快照（版本对齐被测服务）。

### 8.2 测试用例设计要求

**8.2.1 功能用例**（每接口覆盖）：

| 用例类型 | 要求 |
|---|---|
| 正向用例 | 每接口 ≥1 条；三段式结构字段完整性断言（chat 类） |
| 边界用例 | 问句长度 0/1/500/501；分页 size 1/200/201；时间范围跨天/跨月/跨年 |
| 参数校验 | 必填缺失、类型错误、枚举非法 → HRX-1xxx 断言（code + details 双断言） |
| 幂等用例 | 同 `X-Idempotency-Key` 重复提交 → 返回首次结果 + `X-Idempotent-Replay: true`，无副作用翻倍 |
| 乐观锁 | `If-Match` 版本冲突 → 409 |

**8.2.2 权限越权用例（安全验收核心，100% 拦截）**：

| 用例组 | 断言 |
|---|---|
| 功能越权 | HRBP 调用 `admin:*`、无 `export:apply` 调导出 → 403/HRC-2002 |
| 数据范围越权 | HRBP（仅研发范围）问「销售部在职人数」→ 403/HRC-2003 + 审计记录；结果集不含范围外数据且 total 不含该部分（US-02 AC2） |
| 字段越权 | 无授权角色在表格/图表/导出/SQL查看四个出口获取薪酬明文 → 全部 HRC-2004 或脱敏值（PRD 9.4） |
| IDOR | 访问他人 session/report/export → 404（不泄露存在性） |
| 订阅链接转发 | 无权限用户打开推送链接 → 按其权限渲染/拦截（BR-13） |

**8.2.3 SSE 流式用例**：

| 用例 | 断言 |
|---|---|
| 事件顺序 | `MESSAGE_DELTA → TOOL_CALL_* → ANSWER_DONE`，`seq` 单调递增 |
| 澄清流 | `INTERRUPT` 后暂停；应答后续流至 `ANSWER_DONE`；口径反映所选选项 |
| 断线恢复 | 中途断开带 `Last-Event-ID` 重连 → 回放无丢失无重复；窗口过期 → HRS-3004 引导全量拉取 |
| 心跳 | 15s 无业务事件时收到 `HEARTBEAT` |
| 异步转换 | 构造 >30s 查询 → `ASYNC_RUNNING` 收流，任务完成后可拉取结果 |
| 降级 | 关闭 vLLM → 模板内问句返回 200 + `degraded=true`；模板外问句返回 HRA-4001 |

**8.2.4 性能用例**（Locust，staging 执行）：按 4.1 指标设计场景——简单问数 P95<3s、复杂分析 P95<10s、澄清 P95<1.5s、100 QPS 持续 10 分钟错误率 <0.1%、SSE 3000 并发连接稳定、权限改写增量 ≤200ms。

### 8.3 验收标准

| 类别 | 通过标准 |
|---|---|
| 契约质量 | Spectral lint 0 error；Pact 契约测试全部通过；oasdiff 无未评审破坏性变更 |
| 功能 | P0 接口用例通过率 100%，严重/致命缺陷清零；P1 ≥95% 且无严重级（对齐 PRD 9.1） |

### A.3 服务内 API（CH-5，契约同 OpenAPI，此处仅列边界）

| 调用方 → 提供方 | 用途 | 备注 |
|---|---|---|
| chat-service → agent-gateway | 提交问答/归因任务、查询任务状态 | REST + SSE；携带 `tool_context_token` / `invocation_id`（非浏览器 JWT 透传） |
| chat/report/subscription → authz-service | 权限裁决（功能/范围/字段） | OpenFeign；结果含权限指纹 |
| chat/report → semantic-service | 语义对象解析 | — |
| AI 运行时 → mcp-server | 见 2.9 MCP 四工具 | JSON-RPC over HTTP |
| admin-service → 各服务 | 管理后台聚合查询（只读） | D-1：禁止跨库直查 |
