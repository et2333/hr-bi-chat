## 2. 业务愿景与价值流设计

### 2.1 业务愿景

**让每一位HR用一句话获得可信的人力数据洞察**——将"取数周期从天级降到秒级、口径从分歧到统一、决策从经验到数据"三项业务价值产品化。

### 2.2 价值流地图（Value Stream Map）

#### VS-1 人力数据洞察获取（主价值流）

| 阶段 | 业务活动 | 触发 | 价值增量 | 对应能力 | 需求追溯 |
|---|---|---|---|---|---|
| V1.1 提问 | 用户自然语言表达数据诉求 | 用户输入 | 需求被表达 | C2.1 | FR-01 |
| V1.2 理解 | 意图识别、歧义澄清、上下文继承 | 问句提交 | 诉求被准确理解 | C2.1/C2.2 | FR-01~03 |
| V1.3 取数 | 语义解析→权限裁决→安全执行 | 理解完成 | 数据被可信获取 | C2.3/C4.x | FR-01/BR-01/02 |
| V1.4 呈现 | 结论摘要+明细+图表+口径 | 数据返回 | 数据被理解 | C2.4 | FR-04/07 |
| V1.5 洞察（增强） | 对比/下钻/归因 | 用户追问 | 数据变成判断 | C2.5/C2.6 | FR-08~11 |
| V1.6 反馈 | 评价/纠错/偏好沉淀 | 答案曝光 | 体验闭环 | C2.7 | FR-06 |
| V1.7 沉淀 | 答案转报表资产 | 用户保存 | 一次洞察→可复用资产 | C3.1 | FR-12 |

#### VS-2 报表资产运营

```
创建报表 → 配置参数 → 定时刷新 → 订阅分发 → 权限受控访问 → 失效治理
（FR-12/13/14；价值：分析成果从"个人产出"到"组织资产"）
```

#### VS-3 数据口径治理

```
口径发现（badcase/新指标诉求）→ 口径定义 → 审批发布 → 版本生效 → 订阅方通知
（FR-21/BR-04；价值：全公司"一个指标一个数"）
```

#### VS-4 安全合规保障（横向价值流）

```
授权申请 → 权限裁决 → 行级/字段级控制 → 敏感操作审计 → 权限回收
（FR-17~20/BR-02/03/11；价值：敏感HR数据"可用不可见、操作必留痕"）
```

### 2.3 价值流-干系人矩阵

| 价值流 | HRBP | HRD | CHO | 数据管理员 | 系统管理员 |
|---|---|---|---|---|---|
| VS-1 | 发起者 | 发起者 | 发起者 | 支撑（口径） | 支撑（权限） |
| VS-2 | 参与者 | 发起者 | 受益者 | 支撑 | — |
| VS-3 | 触发者（反馈） | 审批者 | — | 发起者 | — |
| VS-4 | 申请者 | 审批者 | 审批者 | — | 执行者 |

## 4. 业务领域模型定义（DDD）

### 4.1 领域划分

| 域类型 | 子域 | 战略地位 |
|---|---|---|
| **核心域** | 语义问答域、分析洞察域 | 产品差异化所在，最高投入 |
| 支撑域 | 报表订阅域、语义治理域 | 支撑核心价值交付 |
| 通用域 | 权限安全域、数据集成域、审计域 | 行业通用方案，够用即可 |

### 4.2 限界上下文（Bounded Context）

| 上下文 | 使命 | 核心聚合 | 语言边界（术语在本上下文含义） |
|---|---|---|---|
| BC-1 会话上下文 | 管理用户对话与交互生命周期 | 会话Session、轮次Turn、答案Answer、澄清Clarification、反馈Feedback | 「答案」=一次问答的完整三段式结果 |
| BC-2 语义解析上下文 | 将自然语言映射为语义层对象 | 查询意图QueryIntent、语义查询SemanticQuery | 「查询」=指标+维度+筛选+时间范围的结构化描述，非SQL |
| BC-3 语义层上下文 | 业务语言的统一定义与版本 | 指标Metric、维度Dimension、同义词Synonym、口径版本MetricVersion | 「口径」=唯一生效版本的业务定义 |
| BC-4 查询执行上下文 | 安全可信地执行取数 | 执行任务QueryTask、白名单校验、结果集ResultSet | 「执行」=只读SELECT，无任何写语义 |
| BC-5 洞察上下文（V2） | 归因与报告生成 | 归因任务AttributionTask、假设Hypothesis、贡献度Contribution | 「归因」=辅助分析结论，必须携带置信度与免责声明 |
| BC-6 报表上下文 | 报表资产与订阅 | 报表Report、组件Component、订阅Subscription、快照Snapshot | 「快照」=某时点按收件人权限渲染的数据版本 |
| BC-7 权限上下文 | 三层权限裁决 | 角色Role、组织授权OrgGrant、字段策略FieldPolicy | 「可见范围」=行级×字段级裁决的交集 |
| BC-8 集成上下文 | 源系统数据接入 | 数据源DataSource、同步任务SyncTask、质量结果QualityResult | 「就绪」=T+1任务成功且质量校验通过 |
| BC-9 审计上下文 | 全链路留痕 | 审计事件AuditEvent | 独立上下文，被所有上下文依赖（单向） |

### 4.3 上下文映射（Context Map）

```
                    ┌──────────────┐
                    │ BC-1 会话     │
                    └──┬───────┬───┘
         提交查询(OHS) │       │ 呈现结果(CF)
              ┌───────▼──┐ ┌──▼────────┐
              │BC-2 语义解析│ │BC-3 语义层 │◄──客服语言(UD)──BC-7权限(读口径适用范围)
              └───┬──────┘ └──▲────────┘
                  │共享语义对象(P2P)  │元数据查询(UD)
              ┌───▼──────────┴─┐
              │ BC-4 查询执行    │──权限改写(OHS)──▶BC-7 权限
              └───┬────────────┘         │
                  │异步任务(事件)          │鉴权(UD)
              ┌───▼────────┐      ┌─────▼──────┐
              │BC-5 洞察V2  │      │ BC-9 审计   │◄──全部上下文单向发布事件(ACL)
              └────────────┘      └────────────┘
              BC-6 报表 ──取数(P2P,复用BC-4)──▶BC-4 ；──权限校验──▶BC-7
              BC-8 集成 ──数据就绪事件(Pub/Sub)──▶BC-4/BC-3(时效标注)
```

| 映射模式 | 说明 |
|---|---|
| OHS 开放主机服务 | BC-2/4/7以标准化接口（MCP/REST）对外提供能力，防腐层由调用方实现 |
| UD 遵奉者 | BC-7权限上下文遵奉BC-3语义层对"敏感字段"的定义，不自行维护副本 |
| P2P 合作关系 | BC-2与BC-4共享「语义查询对象」结构，由统一Schema治理 |
| ACL 防腐层 | 所有上下文→BC-9审计经统一事件适配，审计模型不感知来源细节 |
| Pub/Sub | BC-8发布「数据就绪/延迟」事件，BC-4订阅以标注时效，BC-1订阅以更新答案标注 |

### 4.4 核心聚合设计（战术建模）

#### 聚合A：会话（BC-1聚合根）

| 组成 | 类型 | 说明 |
|---|---|---|
| Session（聚合根） | 实体 | 属性：id、用户、标题、状态(活跃/上下文过期/归档)、最近活跃时间 |
| Turn | 实体 | 一问一答；引用Answer与Clarification |
| Clarification | 值对象 | 澄清问题+选项+用户选择（沉淀为偏好） |
| Answer | 实体 | 三段式结果引用 + 口径版本号 + 图表推荐 + 数据更新时间戳 |
| Feedback | 值对象 | 点赞/点踩+原因分类（进入BC-2质量运营） |

**不变量**：Answer必须携带口径版本与数据时间戳（BR-09）；会话内Turn有序且不可篡改（审计要求）。

#### 聚合B：语义查询（BC-2聚合根）

| 组成 | 类型 | 说明 |
|---|---|---|
| QueryIntent | 实体 | 类型（查询/分析/操作/闲聊）+ 置信度 |
| SemanticQuery | 值对象 | 指标[]、维度[]、筛选条件{}、时间范围、组织范围（用户声明） |
| Ambiguity | 值对象 | 歧义类型+澄清候选（规则见§7.2决策表D-1） |

**领域事件**：`QueryClarified`（澄清完成）、`SemanticQueryComposed`（语义查询生成）。

#### 聚合C：指标（BC-3聚合根）

| 组成 | 类型 | 说明 |
|---|---|---|
| Metric（聚合根） | 实体 | 名称、主题域、公式、默认周期、可用维度[] |
| MetricVersion | 实体 | 版本号、状态(待审批/生效中/已驳回/历史)、生效时间、变更说明 |
| Synonym | 值对象 | 同义词组，命中计数 |

**不变量**：同一时刻仅一个版本「生效中」（BR-04）；版本状态机见§5.6。

#### 聚合D：报表（BC-6聚合根）

| 组成 | 类型 | 说明 |
|---|---|---|
| Report（聚合根） | 实体 | 名称、参数（组织/周期/筛选）、状态(草稿/已保存/已删除) |
| Component | 实体 | 图表/表格组件定义 |
| Subscription | 实体 | 频率、渠道、收件人[]、状态 |
| Snapshot | 实体 | 快照文件引用+生成时间+渲染权限快照 |

**不变量**：Snapshot生成时冻结收件人权限快照，访问时仍实时校验（BR-13）；删除已订阅报表须先停订阅（原型6.3）。

#### 聚合E：权限授予（BC-7聚合根）

| 组成 | 类型 | 说明 |
|---|---|---|
| OrgGrant（聚合根） | 实体 | 授权对象(用户/组)、组织节点[]（含下级）、生效/失效时间 |
| FieldPolicy | 实体 | 字段→策略（隐藏/脱敏/明文-需审批）×角色 |
| FunctionGrant | 实体 | 功能权限点（明细/导出/订阅/管理） |

**不变量**：权限裁决结果缓存键必须含权限版本指纹（BR-05）；变更5分钟全链路生效（BR-12）。

### 4.5 领域事件目录

| 事件 | 发布方 | 订阅方 | 业务意义 |
|---|---|---|---|
| QuestionSubmitted | BC-1 | BC-9审计 | 取数行为开始留痕 |
| SemanticQueryComposed | BC-2 | BC-9 | 解析结果留痕（含SQL摘要） |
| PermissionDenied | BC-7 | BC-1/BC-9 | 越权拦截，触发无权限态 |
| DataReadCompleted | BC-4 | BC-1/BC-9 | 返回行数留痕 |
| MetricVersionPublished | BC-3 | BC-6订阅方通知/BC-2缓存失效 | 口径变更生效 |
| DataSourceReady / DataSyncDelayed | BC-8 | BC-4时效标注/BC-1答案标注 | 数据时效变化 |
| ReportSnapshotGenerated | BC-6 | 分发引擎 | 快照可推送 |
| ExportRequested / ExportCompleted | 任意 | BC-9 | 导出全流程审计（BR-06） |
| AttributionCompleted | BC-5(V2) | BC-1 | 归因结论返回（含免责校验结果） |

## 5. 核心业务流程设计

### 5.1 BP-01 智能问数流程（主流程，泳道视角）

```
泳道：用户 │ 会话上下文 │ 语义解析 │ 权限上下文 │ 查询执行 │ 审计

用户:     [输入问句]──────────────────────────────────────────▶
会话:      │创建Turn │路由分发
解析:      │        │意图分类 ─歧义─▶ [澄清反问] ─用户选择─▶ 语义查询生成
权限:      │                          │ 权限裁决(行级+字段级)
执行:      │                          │ 白名单校验 → 只读执行 → 结果集
会话:      │◀─ 三段式渲染(结论/表格/图表+口径+时效) ◀─┘
审计:      [问句]…[SQL摘要]…[行数]…[导出操作] 全程事件流 ──────────▶
用户:     [反馈/追问/存报表/导出]
```

**关键分支**：
- 意图=归因 → 转BP-03；意图=操作（生成报表）→ 转BP-04
- 权限拒绝 → NoPermission态（流程终止，不暴露被过滤内容存在性）
- 执行>30s → 异步态（后台完成推送，PRD 5.4）

### 5.2 BP-02 多轮对话与上下文管理

| 步骤 | 规则 |
|---|---|
| 1. 追问解析 | 识别指代类型：主题继承（换组织）/条件修改（换粒度）/对比延伸（加同比） |
| 2. 上下文合并 | 继承字段显式展示（原型：上下文状态条），用户可✕移除 |
| 3. 冲突处理 | 新条件覆盖旧条件；时间与组织冲突时反问确认 |
| 4. 过期处理 | 30分钟无交互→上下文清空，轻提示（BR-08） |

### 5.3 BP-03 归因分析流程（V2）

```
[指标异动问题] → 归因意图识别 → 预算约束下发(20次LLM/30次工具/120s)
→ Leader生成假设集(组织/司龄/序列/离职类型四维)
→ 并行取数验证(fan-out≤5) → 沙箱计算贡献度
→ 假设不足? ─是→ 补充假设(≤2轮) ─┐
              否                  │
→ Writer结构化结论(贡献度排序+置信度+免责声明)
→ 合规校验(免责声明断言+脱敏扫描) → 归因卡渲染
失败/预算触达 → 降级为基础对比图+"归因服务繁忙"
```

### 5.4 BP-04 报表创建与订阅流程

| 阶段 | 步骤 | 规则 |
|---|---|---|
| 创建 | 问答转存 / 模板实例化 / 拖拽搭建 | 保存校验：名称≤30字、≥1组件；继承问答时口径版本 |
| 刷新 | XXL-Job定时 → 生成快照 | 快照冻结权限渲染上下文（聚合D不变量） |
| 分发 | 按收件人逐个权限校验 → 邮件/IM推送 | 推送链接访问时二次实时校验（BR-13） |
| 失败 | 重试3次(5/15/30min) → 通知所有者 | 状态机：待执行→执行中→成功/失败 |

### 5.5 BP-05 数据集成与质量保障流程

```
源系统 ─CDC(异动,≤15min)─┐
       ─T+1批量(06:00前)─┴▶ 入仓校验(6.5规则) ─通过▶ 数据就绪事件(时效标注更新)
                              │失败
                              ▼
                        隔离区+告警数据管理员 ─人工修复─▶ 重灌
```

### 5.6 BP-06 口径治理流程（审批流）

```
[发现口径诉求：badcase/新指标] → 数据管理员定义/修改 → 提交审批
→ HR数据负责人审批 ─通过→ 新版本发布(旧版本转历史) → 通知订阅相关报表用户 → 缓存失效
                    └驳回→ 修改重提（线上保持旧口径，BR-04）
```

### 5.7 BP-07 权限申请与变更流程

```
[HRBP申请扩大范围/明文授权] → 直属上级+数据Owner双人审批(敏感)
→ 管理员执行授权 → ≤5分钟全链路生效(含缓存失效广播) → 审计留痕
[定期权限复核(季度)] → 离职/转岗自动回收(对接HRIS异动事件)
```

## 8. 系统边界与接口规范

### 8.1 业务边界定义

| 边界 | 边界内（本系统责任） | 边界外（明确不做） |
|---|---|---|
| 功能边界 | 自然语言问数/分析/报表/订阅/语义治理/权限审计 | HR业务流程办理（入离职审批等）；数据写回；非HR域分析 |
| 数据边界 | HR域只读镜像+自产业务数据（会话/报表/口径） | 源系统主数据的创建与修改 |
| 智能边界 | 语义理解、SQL受控生成、归因辅助 | 自主决策（归因仅供辅助，BR-10）；对人的评价性结论 |
| 责任边界 | 答案在权限与口径层面的正确性 | 源数据本身错误的修正（提示+隔离，责任在源系统） |

### 8.2 业务级接口契约（对内）

| 接口族 | 提供方→消费方 | 业务语义 | 契约形式 |
|---|---|---|---|
| 问答提交 | web-app→chat | 提交问句，约定SSE事件流（MESSAGE_DELTA/INTERRUPT/ANSWER_DONE等） | REST+SSE，ARCH V-06 |
| 语义查询 | BC-2→BC-4 | 传递SemanticQuery+权限上下文，返回ResultSet（含口径元数据） | MCP工具：semantic_query |
| 权限裁决 | BC-7→BC-2/4/6 | 输入用户+语义对象，输出可见范围+字段策略 | MCP工具：permission_check |
| 口径查询 | BC-3→BC-2 | 指标/维度/同义词定义（带版本） | MCP工具：get_semantic_meta |

| 审计上报 | 全部→BC-9 | 标准化审计事件（ACL适配） | 事件Schema |

**契约治理**：接口Schema单一事实源入Git仓库hrchat-deploy；破坏性变更需业务架构评审（§11）。

### 8.3 接口规范统一约束

| 约束 | 内容 |
|---|---|
| 幂等 | 写接口必带Idempotency-Key；查询任务提交以task_id幂等 |

## 9. 异常处理策略

### 9.1 业务异常分类体系

| 类别 | 典型场景 | 业务处理原则 |
|---|---|---|
| E1 输入类 | 意图无法识别、超出500字、纯闲聊 | 引导而非报错：示例问句+反馈入口；不消耗查询资源 |
| E2 权限类 | 越权问句/字段、导出无授权、订阅链接越权 | 体面拒绝：明确告知缺什么权限，不暴露被过滤数据存在性；全部审计 |
| E3 解析类 | 指标不存在、维度组合非法、时间表达无法解析 | 澄清兜底（D-1）；口径缺失转「口径诉求」进入VS-3治理流 |
| E4 数据类 | 同步延迟、质量校验失败、结果为空 | 时效标注（BR-09）；空结果引导调整条件；不阻断主链路 |
| E5 执行类 | 查询超时、Doris过载、SQL被白名单拦截 | 异步化（>30s转后台）；熔断降级（D-4）；拦截记安全日志 |
| E6 智能类（V2） | 归因预算触达、Agent卡死、结论校验失败 | 强制收敛为部分结论并明示；降级为基础对比图（BR-16） |
| E7 系统类 | 网关过载、依赖中间件故障 | 分级降级梯度L0-L3；前端始终告知当前服务状态 |

### 9.2 异常-降级-补偿矩阵

| 异常 | 即时响应 | 后台补偿 | 用户通知 | 审计 |
|---|---|---|---|---|
| E1 | 兜底话术 | 进badcase库 | — | 记录 |
| E2 越权 | 无权限态 | — | — | **必记**（安全事件关联RB-05） |
| E3 | 澄清卡 | 新口径诉求工单 | 口径上线后模板消息 | 记录 |
| E4 延迟 | 带标注答案 | 同步修复后自动刷新缓存 | 答案内标注 | 记录 |
| E5 超时 | 异步态卡 | 完成后推送 | 站内通知 | 记录 |
| E6 | 部分结论/降级 | 任务留痕供复盘 | 卡内明示 | 记录+质量看板 |
| E7 | 降级提示条 | 混沌演练验证恢复 | 全局Banner | 告警 |

### 9.3 业务补偿事务设计

| 场景 | 补偿策略 |
|---|---|
| 订阅推送部分收件人失败 | 逐收件人独立事务；失败重试3次；不因个别人失败阻塞整批 |
| 报表保存时答案口径已变更 | 保存动作锁定保存时点版本；若口径已下线则提示用户确认后按新口径重建 |

| 归因中间结果落盘后失败 | Checkpoint支持断点续跑（≤24h）；过期则任务废弃重提 |

### 10.2 集成清单与模式

| 集成对象 | 方向 | 集成模式 | 数据/事件 | 频率与SLA | 失败策略 |

### 10.3 集成设计原则

1. **只读单向**：数据流严格"源→镜像"，事件流"镜像→分析"，无回写（BR-01）
2. **适配器隔离**：IM三平台差异封装在通道适配器；源系统差异封装在集成层连接器（Connector插件式，新增源不改核心）
3. **事件驱动时效**：CDC事件同时驱动数据就绪与答案时效标注（Pub/Sub，§4.3）
4. **凭证最小化**：源系统只读账号；凭证入Secret管理，季度轮换
5. **人事联动安全**：订阅HRIS离职/转岗异动事件，自动触发权限回收（BP-07）——**权限生命周期与人事生命周期绑定**
